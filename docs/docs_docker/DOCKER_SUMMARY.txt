🔧 COMANDOS ESENCIALES:
================================================================================

INICIAR/DETENER:
  docker-compose up -d              # Iniciar todo
  docker-compose down               # Detener todo
  docker-compose restart            # Reiniciar todo
  docker-compose stop               # Detener sin eliminar

VER ESTADO:
  docker-compose ps                 # Ver estado de servicios
  docker-compose logs -f            # Ver logs en tiempo real
  docker stats                      # Ver recursos (CPU, memoria)

EJECUTAR COMANDOS:
  docker-compose exec backend npm run lint
  docker-compose exec backend npm install
  docker-compose exec backend npx prisma migrate dev
  docker-compose exec backend sh    # Acceder a shell

BASE DE DATOS:
  docker-compose exec backend npx prisma studio
  docker-compose exec postgres psql -U music_user -d music_streaming_platform

LIMPIAR:
  docker-compose down -v            # Eliminar todo (⚠️ BORRA DATOS)
  docker volume prune               # Limpiar volúmenes no usados
  docker image prune -a             # Limpiar imágenes no usadas

💡 CARACTERÍSTICAS PRINCIPALES:
================================================================================

✅ MULTI-STAGE BUILD
   - Imagen final 3x más pequeña
   - Solo dependencias de producción en runtime

✅ HOT RELOAD
   - Backend: cambios se reflejan automáticamente (tsx watch)
   - Frontend: cambios se reflejan automáticamente (Vite HMR)

✅ VOLÚMENES PERSISTENTES
   - Datos de BD persisten
   - Archivos subidos persisten
   - Logs persisten

✅ HEALTH CHECKS
   - Servicios verifican que están listos
   - Reintentos automáticos

✅ RED COMPARTIDA
   - Servicios se comunican por nombre
   - DNS automático

✅ DESARROLLO Y PRODUCCIÓN
   - Mismo setup para ambos
   - Fácil de adaptar

🐛 TROUBLESHOOTING RÁPIDO:
================================================================================

PROBLEMA: "Port already in use"
SOLUCIÓN: Cambiar puerto en docker-compose.yml
          De: "3000:3000"
          A:  "3001:3000"

PROBLEMA: "Cannot connect to database"
SOLUCIÓN: docker-compose logs postgres
          docker-compose restart postgres

PROBLEMA: "Changes not showing up"
SOLUCIÓN: docker-compose build --no-cache
          docker-compose restart

PROBLEMA: "Everything is broken"
SOLUCIÓN: docker-compose down -v
          docker-compose build --no-cache
          docker-compose up -d
          docker-compose exec backend npx prisma migrate dev

🎓 CONCEPTOS CLAVE:
================================================================================

IMAGEN
  - Plantilla para crear contenedores
  - Se construye una sola vez
  - Comando: docker-compose build

CONTENEDOR
  - Instancia en ejecución de una imagen
  - Puede haber múltiples
  - Comando: docker-compose up -d

VOLUMEN
  - Almacenamiento persistente
  - Los datos persisten incluso si eliminas contenedores
  - Comando: docker volume ls

RED
  - Permite comunicación entre contenedores
  - Los servicios se resuelven por nombre
  - Comando: docker network ls

DOCKERFILE
  - Instrucciones para construir una imagen
  - Cada línea crea una capa
  - Archivo: app-music/Dockerfile, client-web/Dockerfile

DOCKER-COMPOSE
  - Define múltiples servicios y cómo se relacionan
  - Orquesta todo
  - Archivo: docker-compose.yml
